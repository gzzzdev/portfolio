# aiV2 — v2 AI도우미 지도

**여기는 지도다. 설계 논거는 각 파일 머리말이 정본이고, 여기에 요약을 다시 적지 않는다.**
두 벌이 되는 순간 한쪽이 거짓말을 시작한다.

## 한 턴은 LLM을 두 번 부른다

판단은 그 사이에서 앱이 한다 — 뭐가 있는지 아는 쪽이 판단하고, 모르는 쪽은 문장만 쓴다.

```
말 → ① 번역 → ② 실행 → ③ 판정 → ④ 설명 → ⑤ 버튼
```

| 단계 | 하는 일 | 어디 |
|---|---|---|
| ① 번역 | 사용자의 말 → `PlanV2` (스키마 O · 대화기록 X · `lite`) | `planner.ts` 의 `계획조회V2()` |
| ② 실행 | 계획대로 거르고 센다 | `source.ts` 의 `조회()` · `plan.ts` 의 `계획실행V2()` |
| ③ 판정 | 되는가 / 왜 안 되는가를 앱이 정한다 | `l/AI_CopilotV2.vue` 의 `판정하기()` |
| ④ 설명 | 확정된 사실 → 문장 (스키마 X · 대화기록 O) | `서술()` → `composables/useChatbot.ts` |
| ⑤ 버튼 | 앱이 만들고, **누르는 건 언제나 사용자** | `버튼만들기()` |

①과 ④는 같은 `/api-etc/ai/chat` 으로 나가는데 거는 것이 반대다.

## 파일별 소유

| 무엇 | 정본 |
|---|---|
| 무엇을 볼지 (모델과 aiV2가 만나는 **유일한** 지점) | `sources.ts` |
| 저장소 → 소스 어댑터 · 어휘 · 주소 변환 | `source.ts` |
| 계획의 축과 실행 | `plan.ts` |
| 번역 호출 · 스키마 조립 · 계획 교정 | `planner.ts` |
| 판정 · 버튼 · 화면 몰기 | `app/components/l/AI_CopilotV2.vue` |
| 채팅 상태 · 전송 창 (파이프라인을 모른다) | `app/composables/useChatbot.ts` |
| 대화 밖에서 온 근거 (화면 선택) | `../ai/화면문맥.ts` — v1 것을 그대로 쓴다 |

## 이 파이프라인이 지키는 것 셋

각 파일에 다시 적지 않는다. 어긋나는 자리에서만 그 자리의 사정을 적는다.

1. **행 데이터는 LLM에 가지 않는다.** 프롬프트에 오르는 건 어휘(소스·건수·축·행동 키)뿐이라
   크기가 건수와 무관하다. 행이 1만 건이어도 프롬프트가 그대로다.
2. **세는 것·주소를 만드는 것은 앱이 한다.** 앱이 이미 정확히 쥔 값을 LLM더러 옮겨 적게 하면
   토큰을 쓰면서 틀릴 여지만 생긴다.
3. **실행은 언제나 사용자의 클릭이다.** LLM은 행동을 제안만 하고, 무엇을 제안할 수 있는지는
   `sources.ts` 의 화이트리스트가 정한다 — 모델에 `do*` 를 추가했다고 권한이 따라 늘지 않는다.

## MCP 서버로 바꾸지 않는다 (2026-09-08 결정)

**지키는 것 셋이 전부 클라이언트 서비스 모델 위에 서 있다.** 필터는 행을 받는 클로저고
(`model*.필터조건ss`의 `(a) => a.원산지 === 곳`), `isDeleted`는 `BaseModels2.list` getter가 거르고,
빈 날짜가 "오늘이 아니라 모른다"인 것도 getter가 정한다. 서버(`server/api/v[01]/[table]`)는
`select('*')` 한 줄이라 이 중 아무것도 모른다 — REST가 CRUD와 1:1인 건 그 층이 얇아서지
설계가 맞아떨어져서가 아니다.

MCP는 프로세스 경계를 넘는 서버 프로토콜인데, 이 파이프라인에는 넘을 경계가 없다
(LLM만 밖에 있고 데이터·행동은 같은 브라우저 안이다). 그래서 어디에 붙여도 셋 중 하나가 깨진다:

- 툴 결과는 정의상 **행**이다 → 1항이 첫 호출에서 죽는다
- 툴 호출은 정의상 **실행**이다 → 3항이 죽는다
- `tools/list`는 정적이라 턴마다 자리를 없애는 `계획스키마V2`를 못 흉내낸다 →
  틀린 답이 **표현 불가능**에서 **호출 후 거절**로 내려앉는다 (lite 에게는 그 차이가 크다)

순서를 뒤집어도(MCP를 먼저 정의하고 나중에 연결) 결론이 같다. 붙일 수 있으려면 서비스 층이
서버에서도 살아야 하는데, 그건 이 파이프라인이 아니라 아키텍처 이전 얘기다.

**다만 MCP가 요구했을 것 하나는 따로 값한다** — `do*`의 인자 선언이다. 지금 행동 ABI는
`i행동버튼.onClick(값?: string)` 한 칸이라(`app/components/view/1.ts`) `PlanV2.행동값`도 문자열
하나고, `AI_CopilotV2.vue`의 `칸값한개로찾기`가 그 값이 어느 칸 것인지를 휴리스틱으로 찍는다.
`자동버튼s`에 인자를 선언하면 그 추측이 통째로 없어진다 — MCP와 무관하게.

**다시 볼 조건:** 판정·필터가 서버에서도 도는 날. 외부 에이전트가 실데이터를 읽을 실제 용무는
여기가 아니라 REST 쪽 일이고, 그 전에 `db_supabase`가 `isDeleted`와 공개투영을 `db_low`만큼
알아야 한다(지금은 모른다).

## 손대기 전에

- **`planner.ts` 의 `계획지침`·`행동지침`·`생성지침`·`수정지침`·`필터지침`·`탭지침`·`지목지침`·`화면지침`,
  `AI_CopilotV2.vue` 의 `시스템프롬프트`와 `서술()` 의 지시문은 주석이 아니라 LLM에 나가는 프롬프트다.**
  길다고 줄이면 동작이 바뀐다.
- **v1(`../ai/`)이 실사용이고 v2가 실험장이다.** 이름은 v2가 새것이지만, 실제로 뜨는 도우미는
  `layouts/default.vue` 가 올리는 v1이고 v2는 `layout-v2`·`layout-p` 두 셸뿐이다(소스가 `v2AI소스s`·`personaAI소스s` 로 갈린다).
  v2에서 검증된 것을 v1로 옮기는 방향이므로, **v1을 고칠 때 v2를 같이 보지 않아도 된다.**
  반대로 v2에 없는 축(본문 발췌·글 초안·편집 중인 화면)을 v2로 복사해 오지 말 것 —
  v2 모델은 필드가 `label` 한 열이라 그 기계가 매 턴 빈 값으로 흐른다.
